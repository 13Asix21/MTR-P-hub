## 一、已核实的事实（本轮实测）

### 1.1 目标文件夹真实存在，且乐享支持多层目录

用浏览器打开你给的公司知识库链接，展开 `01 - 研发项目` 后读到：

```
自动化软件组（space 10cf12a04dd04d30bc99098d42884ce5）
└── 01 - 研发项目
    ├── 01-***项目【负责人：***】
    ├── 02三角焊带检测项目【负责人：沈乐】
    ├── 03 SG项目砷化镓载板定位【负责人：孙梦炀】
    ├── 04 载板检测机项目【负责人：沈乐/孙永博】
    ├── 05载板清洗线-定位【负责人 倪青云】
    └── 06 PED烧靶位置视觉检测引导【负责人：李元伯】   ← 目标
```

**结论**：三层结构（知识库 → 研发项目 → 06 PED…）**已被证实可行**，不是乐享的能力限制。命名规范也清楚了：`序号 + 项目名 + 【负责人：XXX】`。

### 1.2 关键阻塞：个人 MCP token 访问不到企业空间

| 检查 | 结果 |
| --- | --- |
| 浏览器（公司账号 李元伯） | ✅ 可读，能看到目标文件夹 |
| 个人 MCP token（元.波） | ❌ `code:71 不存在ID为 10cf12a04dd04d30bc99098d42884ce5 的 kb_space 资源` |
| 原因 | **两个不同组织**。个人 token 属于「元.波的组织」，公司库属于「苏州迈为自动化设备有限公司」 |

**这是当前唯一的硬阻塞**：现有 `apps/mtrp-proxy` 用的是个人乐享凭据，触达不到公司空间，因此"传送到公司 06 目录"这条路走不通。

### 1.3 现有传送能力的状态

| 能力 | 现状 | 能否用于本目标 |
| --- | --- | --- |
| 整篇文件导入 `file_import_markdown` | 已实现，实测 16KB 逐字节一致 | ✅ 方式可行，但需企业 token |
| 逐级建文件夹 `_resolve_parent` | 已实现，按 `path` 逐级 `entry_create_entry` | ⚠️ 只能建新目录，**不能定位已存在的同名目录** |
| 目标路径写法 | 当前 `path="MTR-P-验证"` 这类相对路径 | ❌ 无法表达"进入 01 - 研发项目 下" |

**核心缺口**：现有实现是"按路径字符串**新建**目录"，而不是"按名字**查找**已有目录"。往 `06 PED…` 里写，如果走现有逻辑，会在根目录下**新建一个同名的 `06 PED…`**，造成重复目录。这是必须先修的设计问题。

## 二、未满足的前置条件（按阻塞程度排序）

### P0-1　企业级 MCP 凭据（硬阻塞，必须由你提供）

**现状**：只有个人乐享 token，访问不到公司空间。

**需要什么**：苏州迈为企业的乐享 MCP endpoint + token，或企业侧的 API 接入凭据。

**怎么拿**（三条路，任一可行即可）：
1. 乐享企业后台是否有「开放平台 / MCP / API 接入」入口
2. 联系企业乐享管理员申请服务账号
3. 若企业版不开放 MCP，则退到方案 B（浏览器自动化）

**没有这条，纯 API 路线无法推进。**

### P0-2　按名称定位已存在目录（代码缺口）

**现状**：`_resolve_parent` 只会"逐级查找/创建"，但查找靠路径拼接，没有"列子节点按名称匹配"的实现。

**需要什么**：
- 用 `entry_list_children(parent_id)` 列出 `01 - 研发项目` 的子节点
- 按名称精确匹配 `06 PED烧靶位置视觉检测引导【负责人：李元伯】`
- 拿到它的 `entry_id` 作为 `parent_entry_id` 再导入
- **匹配不到时必须报错，不能自动新建**（否则会出现重复目录）

**验收标准**：给定完整路径 → 能定位到已存在目录的 entry_id；路径中任一层不存在 → 明确报错并指出是哪一层。

### P0-3　目标路径的配置与 UI 入口

**现状**：M 库配置里只有「放进哪个文件夹」一个自由文本，语义是"新建"。

**需要什么**：
- 明确区分「新建目录」与「存入已有目录」两种模式
- 支持形如 `01 - 研发项目/06 PED烧靶位置视觉检测引导【负责人：李元伯】` 的多级路径
- 保存前做一次只读校验：路径能否解析、目标是否唯一

### P1-1　写入前的内容校验（防止污染企业库）

**现状**：上传前只校验 SHA 与体积。

**需要什么**：
- 同名文件已存在时的策略（覆盖 / 跳过 / 改名），必须显式选择
- 写入后回读校验（确认字节一致），失败要能告知具体哪一篇

### P1-2　多知识库（多组织）并存

**现状**：M 库只有一个空间 ID，只能在个人组织里用。

**需要什么**：配置层支持"多套乐享凭据"，按目标库切换（个人库 / 公司库）。

### P2-1　浏览器自动化兜底（企业不开放 MCP 时）

**现状**：ego-browser 能打开并读取页面，但没做成可复用的写入通道。

**风险**：靠点击 UI 写入，脆弱且难验证；只能当兜底，不应作为主路径。

## 三、开发计划

### 阶段 A：凭证与定位（前置，必须先做）

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| A1 | 拿到企业 MCP 凭据，配置成独立的第二套乐享连接 | `whoami` 返回公司账号；`lexiang_fetch(space)` 能读到"自动化软件组" |
| A2 | 实现 `resolve_existing_path(space_id, path_segments)`：逐层列子节点按名称匹配 | 用真实路径定位到 `06 PED…` 的 entry_id；错一层能准确报错 |
| A3 | 单测覆盖：完全匹配、部分匹配、**重名两个目录必须报歧义**、某层不存在 | 全部通过，且不产生任何写入 |

> A2/A3 可以**现在就在个人库上开发验证**（`M库范式` 是可写测试库），等 A1 到位后直接切换到公司库。这样不阻塞等待。

### 阶段 B：精准写入

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| B1 | 传送接口支持 `mode: "existing"`，路径按段解析后定位父节点 | 写入落在 `06 PED…` 内，不产生重复目录 |
| B2 | 同名冲突策略（默认跳过并报告，需显式覆盖才替换） | 重复上传同一篇不会产生两份 |
| B3 | 写后回读校验（下载比对 SHA-256） | 字节一致才算成功 |

### 阶段 C：接入界面

| 步骤 | 内容 |
| --- | --- |
| C1 | M 库配置增加「目标目录（多级路径）」+「校验路径」按钮，只读确认能定位 |
| C2 | 传送面板显示完整目标路径，写入后给出 entry 链接 |
| C3 | 批量传送时逐篇显示落点，失败项列出原因 |

### 阶段 D：多库切换（可选）

把乐享凭据做成命名配置（如 `personal` / `company`），传送时可选目标库。

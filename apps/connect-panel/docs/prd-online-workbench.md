### 1.1 原始需求复述

本地版审核工作台已能在本机跑通（1832 篇队列、三动作、撤销、批量、导出、72 项测试资产）。问题是：它只能在雷爹这台机器上、`127.0.0.1:8765` 里用。雷爹要的是**在线工具**——打开一个网址就能审，进度跟着账号走，换台设备接着审。

技术上这件事过去卡在一个点上：浏览器沙箱不让网页读本地磁盘。现在解开的钥匙是 **File System Access API**（`showDirectoryPicker`）：用户亲手选一次目录，网页就拿到该目录的句柄，可以遍历、读文件、算 hash——**做得到只读扫描整套审核域逻辑**。与此同时，台账不能继续躺在 `users.json` 里（那是本机文件），迁到 WorkBuddy cloud-service 云数据库，并用真实账号 ID 做用户隔离。

**"读写对应文件"的准确语义（已拍板，是本轮最重要的边界）**：

| 动作对象 | 在线版是否允许 | 说明 |
|---|---|---|
| 读 Vault 目录结构、读 `.md` 原文、算 sha256、解析 frontmatter、预览正文 | **允许（完整能力）** | 只读，与本地版同输入同输出 |
| 写审核台账（通过/拒绝/跳过/撤销/理由/时间） | **允许** | 写到云数据库，不落到 Vault |
| 写导出清单（JSON/CSV 文件下载） | **允许** | 作为下载文件交给用户，不落到 Vault |
| 写 Vault 正文 / frontmatter / 标签 / 重命名 / 移动 / 删除 | **禁止（红线）** | 浏览器层**无写资格**（授权仅 `mode:'read'`）；属阶段 3/4 Core 提案审批体系范畴，**不因上线而松动** |

一句话：**读是全面的，写只限台账和导出；Vault 一个字节都不动。** 本轮把「零写入」从"我们没写"升级为**"我们没资格写"**——`showDirectoryPicker` 只申请 `mode:'read'`，浏览器层不给写句柄，杜绝误写与后续漂移。这是本轮的零写入红线，也是 QA 的一票否决项之一。

**演进路径（写在此处，防日后口径失真）**：若阶段 3/4 确需写标签/写 frontmatter，**不在在线版就地放宽**，而是单独升级授权为 `readwrite` 并**另立一份 PRD** 走同样的拍板流程；届时零写入红线按新 PRD 划定的范围与审批链调整，本 PRD 的只读口径不被隐式继承为"可以写"。

### 1.2 必须继承的本地版既有口径（不得被"在线化"稀释）

| 口径 | 本地版定义（已拍板） | 在线版要求 |
|---|---|---|
| 扫描范围 | 仅 `2-Permanent`（managed root），排除 `2-Permanent/Resources/MTR-P-System` 与 `2-Permanent/Areas/AI-Assets/_templates` | 完全相同，且排除逻辑必须在 JS 里逐字复刻（见 P0-02） |
| 队列与分母 | 队列 = 扫描到的 `.md` 总数，实测 **1832**（含 12 篇 `INVALID_YAML`）；分母 = 1832 | 相同；数字随实扫变化，不得硬编码 |
| 已审/通过率 | 已审 = 通过+拒绝+跳过；通过率 = 通过 ÷ 已审 | 相同 |
| `INVALID_YAML` 12 篇 | 进队列、标「格式异常」、只给原文预览、三动作不限 | 相同；这是对拍的关键样本 |
| 审核记录六要素 | `(user_id, 相对路径, 动作, 理由, content_sha256, 时间)` | 相同；`user_id` 改为真实账号 ID |
| sha256 语义 | 对**原始字节**（含 BOM/CRLF）算，64 位小写十六进制 | **必须逐字节一致**，JS 侧零容差（见 Q2） |
| 路径键 | NFC 归一 + POSIX 分隔，排序按 `casefold()` | 相同，且字符串逐字节可用于对拍比对 |
| 防旧结论 | 动作必须带客户端读到的 `sha256`，服务端比对不符则拒绝（`CONTENT_CHANGED`） | 相同，比对在 JS 内完成 |
| 导出 | JSON 主 + CSV 副，默认只导 `approved` 且 hash 复核一致 | 字段与 `schema_version` 完全一致，只换落点 |
| 理由 | 可选；点「拒绝」自动展开并聚焦 | 相同 |
| 键盘 | `J/K/A/R/S/U`，焦点在输入框时不拦截 | 相同（P1） |
| 凭据/安全 | 零 traceback 外泄、前端 `textContent` 渲染 | 相同；另加"不向任何第三方域发请求" |

### 1.3 在线版独有的新事实（本地版不存在，必须写死）

| 事实 | 在线版口径 |
|---|---|
| 浏览器 | **仅 Chromium**：Chrome / Edge ≥ 支持 `showDirectoryPicker`（建议 Chrome 108+ / Edge 108+）。Safari / Firefox 一律走不支持提示页，**不做降级实现、不承诺只读兜底** |
| 授权模型 | 每次会话由用户手动点按钮触发 `showDirectoryPicker({mode:'read'})`，用户亲手选中 Vault 根；**绝不自动静默访问**；句柄只能复用用户选过的那个目录，不能越过它；**不申请写权限**（Q3 裁决） |
| 部署 | 纯静态站点（`index.html` + JS + 同源 `manifest.webmanifest` + `sw.js` + `vendor/`），无后端进程、无 FastAPI、无 `127.0.0.1` 依赖，走 WorkBuddy sites 发布 |
| 台账存储 | WorkBuddy cloud-service 云数据库，按账号 ID 隔离；不再是 `users.json`；云不可达时 IndexedDB 缓冲（Q4 裁决） |
| 依赖边界 | HTTP 请求只允许两类：① 同源静态资源（含 vendored `js-yaml`）；② 云数据库 API。**不接入 GitHub / 乐享 / MCP / 任何 CDN / 任何统计脚本** |
| 与本地版隔离 | 两套代码不同目录、不同服务、不同存储，**不得在同一服务里混流**；在线版故障不影响本地版 |

## 2. 产品目标与成功标准

**一句话目标**：让雷爹在**任何一台装了 Chrome 的机器上**，打开一个网址、点一次「选择 Vault 文件夹」，就能接着上次的进度审这 1832 篇——扫描解析结果与本地版逐字节一致，台账在云上、跟账号走、不丢一条，而 Vault 全程零写入。

**成功标准**（四条，正交、可验收、均可量化）：

1. **在线可用率**：在目标 Chromium 版本上，从打开页面到看到可审清单，主路径成功率 100%（不含用户误操作取消授权）；单次全量扫描 1832 篇 ≤ 本地版实测耗时的 2 倍（首版可放宽，但必须给出实测值，不能留空）。**不接受"偶尔成功"**。
2. **授权体验**：首次使用者无需读文档即可完成「选目录 → 扫描 → 审第一篇」；授权动作必须由用户点击触发（以代码审计 + 自动化断言双重确认无静默调用）；取消授权/选错目录两条异常路径均有明确中文提示和重试入口。
3. **对拍全等**：同一份真实 Vault 输入下，JS 引擎输出的扫描清单、sha256、frontmatter 键值、标签集、`mtr_state`、`parse_status`、链接计数与本地 Python 版**逐条逐字段全等**（零容差，见 Q2）。这是**一票否决项**：任一条不等，本期不算交付。
4. **台账不丢**：审核动作写入云台账后，换设备/换浏览器/清缓存重新登录，读回的动作、理由、sha256、时间与写入值完全一致；云端不可达时产生的动作在恢复后自动补传，**不丢、不重、不乱序**。

**不做成什么**：不是 Vault 编辑器、不是内容管理器、不是跨浏览器兼容工程、不是本地版的替代品、不是 M 库发布入口。

## 4. 需求池

优先级：**P0 = 本期必须（缺失即不算完成）**；**P1 = 应有（不得挤占 P0）**；**P2 = 后做**。**P0 共 9 条**（含 1 条对拍验收条与 1 条零写入条）。

### 4.1 P0（本期必须）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| P0-01 | **目录授权与范围绑定**：用户手势触发 `showDirectoryPicker({mode:'read'})`，取得 Vault 根句柄，并把扫描范围锁定到 `2-Permanent`。 | ① `showDirectoryPicker` 只允许在真实用户点击事件栈内调用（不允许定时器/加载时/`useEffect` 触发），代码审计可查；② **已拍板 Q3：只申请只读模式（`mode:'read'`），永不申请 `readwrite`**——这是零写入红线在权限层的根本保障，不是可选优化；③ 选完即校验 `2-Permanent` 存在，缺失则给出「未找到 `2-Permanent`…」提示并停在空态；④ 回显只展示目录名，界面任何位置不展示用户绝对路径；⑤ 用户取消（`AbortError`）不当作错误弹窗，静默回到空态并保留文案「未选择目录」。 |
| P0-02 | **JS 扫描引擎**：在浏览器内遍历授权目录，产出与本地版同构的审核清单。 | ① 遍历顺序、排除规则、`.md` 过滤（大小写、后缀）与 `review_scan.py` 逐条一致，排除两个 excluded root；② 每个文件读为 `ArrayBuffer` → 对**原始字节**算 SHA-256（大写十六进制一律下转、64 位小写）；③ frontmatter 切片规则与 `obsidian_markdown.py::_frontmatter_end` 一致（首行 `---` 才对；无闭合 `---` 判 `INVALID_YAML`；`---` 后不是 mapping 也判 `INVALID_YAML`；`tags` 非 str/list[str] 也判 `INVALID_YAML`；重复键判错）；④ 行内标签正则、代码围栏/行内代码排除、缩进行跳过与主仓逐字符一致；⑤ `mtr_state` 按 `conflict > trial > rarely > unmanaged` 优先级；⑥ 路径键 NFC + POSIX，排序 `casefold()`；⑦ **单篇解析失败不得中断整批**，只标该篇 `parse_status`；⑧ 真实 Vault 跑出 1832/1820/12/unmanaged 1820/conflict 0 与本地版一致。 |
| P0-03 | **单篇只读详情** | 展示相对路径、sha256、字节数、mtime、标签集、`mtr_state`、`parse_status`、frontmatter 有序键值（保留原文本，不美化丢信息）、正文（Markdown 渲染 + 原文切换）、出链数/反链数；`INVALID_YAML` / `INVALID_ENCODING` 篇只给原文模式并明示原因；页面固定标注「只读预览，不写入 Vault」；所有动态值用 `textContent` 渲染，不拼 innerHTML。超 1 MiB 文件按本地版口径给「文件过大，不预览」而不截断当完整。 |
| P0-04 | **三动作 + 撤销 + 理由 + 防旧结论** | 通过/拒绝/跳过互斥可改判（以最后一次为准，历史追加）；撤销回「未审」并记录 `UNDO` 历史；理由可选，点「拒绝」自动展开并聚焦；动作前用当前重读的 sha256 与队列中该篇 sha256 比对，不一致则**拒绝写入**并提示「内容已变更，请重新查看后再决定」（错误码语义对齐 `CONTENT_CHANGED`）；动作成功后不触碰 Vault（见 P0-09）。 |
| P0-05 | **云台账读写 + 用户隔离** | 台账表 schema 必含：表级 `schema_version`；行级 `user_id`（真实账号 ID，非 `default`）、`vault_relative_path`、`action`、`reason`、`content_sha256`、`decided_at`、`updated_at`、`display_name`、`role`；历史表（或同表 `history` 子数组，上限 200 条，`ops ∈ {DECIDE, UNDO, STALE_RESET}`）；主键唯一性 = (`user_id`, `vault_relative_path`)；RLS/隔离规则保证 A 账号读不到 B 账号任何记录；同一账号并发两台设备写入以 `updated_at` 后写覆盖但历史双记；读回结构与本地版 `review.items` 语义等价。 |

## 7. 明确不做

- **不写 Vault**：不改正文、不改 frontmatter、不改标签、不重命名、不移动、不删除、不创建临时文件。**已拍板 Q3：权限层也不申请写权限（仅 `mode:'read'`），浏览器层无写资格**。
- **不写标签、不做分类**：`mtr/trial` / `mtr/rarely` 的写入属阶段 3/4 授权范围，在线版不碰；若阶段 3/4 需要写，**单独升级授权 + 另立 PRD**，不在本 PRD 内放开。
- **不做跨浏览器兼容**：不实现 Safari/Firefox 的 `<input webkitdirectory>` 降级、不做 zip 上传兜底、不做服务端代读。不支持就是提示页。
- **不做后端化**：不部署 FastAPI、不做代理、不在服务端读用户文件；在线版就是静态站点 + 浏览器 + 云数据库。
- **不替换本地版**：本地版继续存在并继续维护；本地版仍是带凭据/MCP/乐享能力的唯一形态；在线版不试图接管四库仪表盘。
- **不做登录/权限拦截逻辑的自研**：账号体系用 WorkBuddy cloud-service 既有能力，`role` 仅存取不拦截。
- **不做 AI 评分/自动通过/自动摘要**。
- **不接第三方分析、不引 CDN、不引 emoji**：`manifest` / `sw` / `vendor/js-yaml` 为仅有的三类同源静态文件例外，运行时零 CDN。

9. 断网后审 5 篇：界面显示「暂存本机（5 条）」，刷新页面（保持同一浏览器）后待同步条数仍为 5（IndexedDB 生效）。
10. 恢复网络：5 条按时间序补传，云端读回 5 条；再刷新不重传（去重键生效）；人为制造一条补传失败，其余 4 条成功且失败条仍待同步。
11. 已安装 PWA 后关闭浏览器重开：显示「继续使用上次授权的目录」，一次点击进入并扫描成功；手动在浏览器设置里撤销该站点权限后，点击该按钮→退回手动选择，无未捕获异常。

### 8.5 不支持浏览器用例

12. 在 Firefox / Safari 打开：出现提示页，文案含「请使用 Chrome 或 Edge」，无假按钮，Console 无未捕获错误，Network 无对本地磁盘/第三方的请求。

### 8.6 批量性能用例（已拍板 Q7）

13. 对 1000 篇样本执行批量读+hash：实测 ≤ 60 秒；decide 每批 50 条 ≤ 3 秒。任一超时，界面必须出现降级提示并切到「批量读 hash + 逐篇 decide（每篇人工确认）」模式，且降级原因文案可见——**不得静默超时、不得只提示失败不给降级路径**。
14. 批量范围内含 `INVALID_YAML` 篇时，确认层显示「其中含 M 篇格式异常」，结果摘要单列该 M 篇。

## 10. 与本地版的关系一句话总结

本地版是**带凭据、能对接 MCP/乐享、跑在本机的完整形态**；在线版是**同一套审核语义的便携形态**——读 Vault 靠用户亲手授权（仅只读权限），写只写台账与导出，Vault 零字节变更且浏览器层无写资格。两者共存，互不替代，共享同一套对拍口径与导出血缘。
